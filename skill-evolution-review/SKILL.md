# Skill 进化

## 触发方式

本 skill **只允许显式触发**。用户手动调用本 skill，或明确说“skill进化”“复盘 skill”“看看 skill 要不要改进”“总结前面的问题并优化 skill 建议”等时，走完整的五步流程（梳理时间线 → 分类问题 → 判断是否改 skill → 输出待审核清单 → 确认后修改）。

用户纠正、提供新标准或资料、推翻假设、任务出现卡点等情况本身都**不得**触发或主动建议 skill 进化；继续完成当前任务即可。

## 目标

对刚完成的一段工作做复盘，回答三类问题：

1. 前面的任务过程中遇到了什么问题。
2. 这些问题是否可能由现有 skill 的指令缺失、触发条件不清、流程顺序不合理、验证门禁不足或报告格式不完整导致。
3. 如果是 skill 问题，应该如何继续优化 skill，并给出可审核的修改建议。

## 工作原则

- 先复盘，后修改。没有得到用户明确确认前，不要实际编辑任何 skill 文件。
- 区分事实、判断和建议。不要把推测写成已确认结论。
- 优先引用当前会话中已经发生的现象、命令结果、失败日志、用户纠正点和已修改文件。
- 如果无法判断是不是 skill 问题，要明确写“证据不足”，并说明还需要什么证据。
- 建议要可执行，最好能定位到具体 skill 文件、章节、规则或触发条件。
- **Less is more，只做必要修改。** 每条建议都要能回答“不加会怎样”——答不上来就不提。优先改小、改准，而不是补长；已有规则能覆盖的不新增，同一条规则不在多处重复表述。写完回头删一遍：例子留一个够用的，不要三个；解释一句说清的，不要一段。
- **删减也是进化。** 发现过时、重复、与当前流程不符或从未被用到的内容，可以提“建议删除”，与新增建议同等对待。skill 越长，关键规则越容易被淹没。

## 复盘流程

### 1. 梳理任务时间线

按自然语言总结刚完成的任务：

- 用户最初要解决什么。
- 过程中做了哪些关键检查、修改、编译、测试或提交。
- 中间遇到过哪些卡点、返工、误判、遗漏或用户追加要求。
- 最终状态是什么。

### 2. 分类问题

把问题分成以下几类：

- **技能指令问题**：skill 中缺少规则、规则太弱、触发条件不清、输出要求不完整。
- **执行问题**：Codex 没有充分遵守已有 skill、命令写错、验证不充分、报告不清楚。
- **环境问题**：服务器、工具、路径、权限、历史工程 blackbox、依赖缺失等。
- **需求演化**：用户后续提出了新标准，原 skill 之前没有覆盖。
- **证据不足**：当前对话或日志不足以归因。

### 3. 判断是否需要改 skill

对每个问题给出判断：

- 是否是 skill 问题：是 / 否 / 部分是 / 证据不足。
- 涉及哪个 skill：例如 `dsp-kernel-auto-verification`、`dsp-spyglass-lint`、`qx-dsp-result-debug`。
- 建议修改位置：章节名、规则附近、触发方式、报告模板或硬规则。
- 修改收益：避免什么重复问题，提升什么检查质量。
- 修改风险：是否会让 skill 变得过重、过慢、过度触发或误伤正常流程。

### 4. 输出待审核清单

必须先输出一份待用户审核的清单，不要直接修改文件。格式如下：

```text
Skill 进化建议：

1. <建议标题>
   - 现象：<前面发生了什么>
   - 归因：<是否是 skill 问题，以及原因>
   - 涉及 skill：<skill 名称>
   - 建议修改：<具体改什么>
   - 预期收益：<改完避免什么>
   - 风险/代价：<可能变慢、变复杂或误触发的地方>
   - 建议操作：建议修改 / 建议删除 / 暂不修改 / 需要更多证据

请确认要执行哪些修改。你可以回复“全部修改”、编号列表，或指出哪些不要改。
```

### 5. 等待确认后再修改

只有当用户明确确认要修改后，才进入实际编辑流程：

- 只修改用户确认的条目。
- 修改前再次读取目标 skill 的相关段落。
- 使用 `apply_patch` 编辑 skill 文件。
- 修改后校验文件可读、UTF-8 正常，并抓取新增规则所在行。
- 最终汇报修改了哪些 skill、哪些章节、每条建议是否已落地。

## 禁止事项

- 不要在首次复盘回答中直接修改 skill。
- 不要把所有执行失误都归咎于 skill。
- 不要建议宽泛空洞的规则，例如“以后更仔细”。
- 不要新增与刚完成任务无关的大段背景知识。
- 不要把临时工程、日志、报告、测试输出加入 skill，除非它们是经过整理的通用流程模板。
